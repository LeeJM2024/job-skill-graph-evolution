# outputs 输出文件说明

本文件夹保存岗位数据流生成与评测系统运行后的所有结果文件。

新的代码执行方式是：

```text
outputs/
  current_run_id.txt
  runs/
    <run_id>/
      本次执行的所有 CSV/JSON/TXT 输出
```

也就是说，每次从第 1 步开始执行时，系统都会在 `outputs/runs/` 下新建一个本次运行文件夹，并把工作流文件、答案表和验证文件都放进去。

如果你看到 `outputs` 根目录下仍有旧 CSV/JSON 文件，那是历史版本生成的结果；新版本脚本不会再把新结果写到根目录。

## 一、最重要的交付文件

如果只是把结果交给外部系统或其他同学使用，优先看当前 run 文件夹中的这 3 个文件。

当前 run id 可通过下面的文件查看：

```text
outputs/current_run_id.txt
```

| 文件 | 用途 | 说明 |
|---|---|---|
| `outputs/runs/<run_id>/job_update_event_stream_generated.csv` | 系统输入数据流 | 最终生成的岗位招聘事件流，输入给你的系统使用。 |
| `outputs/runs/<run_id>/job_demand_monthly_answer.csv` | 岗位需求答案表 | 用来比对系统是否正确识别每个岗位每月 JD 数量变化。 |
| `outputs/runs/<run_id>/job_skill_monthly_frequency_answer.csv` | 技能频率答案表 | 用来比对系统是否正确识别每个岗位下技能频率变化。 |

这三个文件分别对应：

```text
输入：岗位招聘事件流
答案1：岗位需求变化答案
答案2：技能频率变化答案
```

## 二、第 1 步：输入解析与数据画像

这些文件用于说明原始输入数据的质量和可用范围。

| 文件 | 作用 |
|---|---|
| `input_profile.csv` | 每个标准岗位一行，记录真实 JD 数、岗位名称数、技能池规模、样例岗位名称、样例技能和质量备注。 |
| `skill_pool_by_job.csv` | 岗位-技能池明细表，记录每个标准岗位可使用哪些技能，以及技能属于传统技能还是新兴技能。 |
| `input_quality_report.json` | 输入数据质量摘要，例如标准岗位数、源数据行数、无样本岗位等。 |

主要用途：

- 检查 71 个标准岗位中哪些有真实 JD；
- 检查每个岗位有哪些可用技能；
- 为后续技能趋势生成提供基础技能池。

## 三、第 2 步：岗位需求趋势生成

这些文件描述“每个岗位每个月应该生成多少条 JD”。

| 文件 | 作用 |
|---|---|
| `job_demand_monthly_plan.csv` | 岗位-月份-JD 数量计划。第 4 步生成事件流时严格按这个表生成数量。 |
| `job_demand_trend_design.csv` | 岗位趋势设计表。每个标准岗位一行，记录该岗位被分配到的需求变化趋势。 |
| `job_demand_quality_report.json` | 岗位需求计划质量报告，记录总量、趋势分布、无样本岗位等。 |

岗位趋势类型包括：

```text
持续上升
持续下降
先上升后稳定
先上升后下降
稳定波动
间歇出现
消失后再出现
无样本不生成
```

注意：

- `大数据开发工程师` 和 `FPGA工程师` 当前没有真实样本，因此保留在趋势表中，但计划 JD 数为 0。

## 四、第 3 步：技能趋势与技能概率计划

这些文件描述“每个岗位下的技能如何随月份变化”。

| 文件 | 作用 |
|---|---|
| `skill_trend_design.csv` | 技能趋势设计表。每行是一个岗位-技能组合，记录该技能的趋势类型和技能阶段。 |
| `skill_monthly_probability_plan.csv` | 技能月度概率计划。记录每个岗位、每个技能、每个月的出现概率。 |
| `skill_trend_quality_report.json` | 技能趋势质量报告，记录技能数量、趋势分布、岗位覆盖情况等。 |

技能趋势类型包括：

```text
稳定型
持续上升
持续下降
先上升后稳定
先上升后下降
后期突增
间歇出现
```

说明：

- `skill_monthly_probability_plan.csv` 是生成过程中的概率计划，不是最终答案。
- 最终用于比对的是 `job_skill_monthly_frequency_answer.csv`。

## 五、第 4 步：最终事件流生成

这些文件是最终生成数据流及其质量报告。

| 文件 | 作用 |
|---|---|
| `job_update_event_stream_generated.csv` | 最终生成的岗位招聘事件流，是最核心的输入文件。 |
| `event_stream_quality_report.json` | 事件流质量报告，记录生成行数、技能数量分布、字段检查等。 |

事件流字段：

```text
job_id
month
standard_job
job_title
job_responsibility
job_requirement
skills
```

明确不包含：

```text
traditional_skills
new_skills
```

## 六、第 5 步：答案表与最终校验

这些文件是从最终事件流重新计算得到的标准答案和最终报告。

| 文件 | 作用 |
|---|---|
| `job_demand_monthly_answer.csv` | 岗位需求月度答案表。 |
| `job_skill_monthly_frequency_answer.csv` | 技能频率月度答案表。 |
| `final_quality_report.json` | 最终质量报告，汇总事件流、答案表和校验结果。 |
| `run_summary.txt` | 简短运行摘要，适合快速查看本次生成是否正常。 |

建议每次运行后先查看：

```powershell
Get-Content -Encoding UTF8 outputs\current_run_id.txt
Get-Content -Encoding UTF8 outputs\runs\<run_id>\run_summary.txt
```

关键指标应满足：

```text
岗位需求计划不一致数: 0
非法岗位-技能组合数: 0
事件流字段是否匹配配置: True
被禁止字段是否出现: []
```

## 七、其他文件

| 文件 | 作用 |
|---|---|
| `.gitkeep` | 占位文件，用于让 Git 保留 `outputs` 文件夹。现在文件夹已有输出结果，保留或删除都不影响系统运行。 |
| `输出文件说明.md` | 当前说明文档。 |

## 八、哪些文件可以直接交给别人

如果对方只需要运行或评估系统结果，建议提供：

```text
job_update_event_stream_generated.csv
job_demand_monthly_answer.csv
job_skill_monthly_frequency_answer.csv
run_summary.txt
final_quality_report.json
```

如果对方需要复现整个生成流程，则应保留对应的 `outputs/runs/<run_id>/` 文件夹，因为中间文件可以帮助定位每一步生成逻辑。

## 九、不建议随意移动的文件

以下文件在同一个 run 文件夹内被后续脚本读取，移动后如果不修改代码路径，会导致脚本无法继续运行：

```text
input_profile.csv
skill_pool_by_job.csv
job_demand_monthly_plan.csv
job_demand_trend_design.csv
skill_trend_design.csv
skill_monthly_probability_plan.csv
job_update_event_stream_generated.csv
```

因此，当前整理方式是“每次运行放入独立 run 文件夹”，不要在一次流程尚未跑完时移动其中的文件。
