# 岗位数据流生成与评测系统设计说明

## 1. 系统目标

本系统用于自动生成“岗位招聘事件流”数据，模拟不同标准岗位在月度维度上的招聘需求变化，以及岗位内部技能需求随时间变化的过程。

生成结果将用于两类目的：

1. 作为业务系统的输入数据流，模拟招聘 JD 按月进入系统。
2. 作为标准答案，用来和业务系统输出结果进行比对，验证系统是否正确更新岗位与技能需求频率。

系统每次执行时，应基于固定随机种子生成可复现的数据集。

## 2. 时间范围

生成数据的时间范围固定为：

```text
2024-12 至 2026-07
```

共 20 个月。

系统以“月”为最小时间单位，不生成日级数据。

## 3. 数据规模

每次生成的数据流规模控制在：

```text
2000 至 3000 条 JD
```

每条记录代表一个月中出现的一条岗位招聘事件。

每月总 JD 数不固定，由系统根据岗位需求趋势自动生成。

## 4. 使用的标准岗位范围

系统使用当前标准岗位词表中的全部标准岗位。

标准岗位词表路径：

```text
data/input/standard_job_title_dictionary.csv
```

当前标准岗位数量为 71 个。

所有生成的 JD 必须能够映射到这 71 个标准岗位之一。

## 5. 输入数据

### 5.1 标准岗位词表

文件：

```text
data/input/standard_job_title_dictionary.csv
```

用途：

- 提供标准岗位集合；
- 提供标准岗位所属大类；
- 限定最终生成数据中允许出现的 `standard_job`。

### 5.2 岗位技能表

文件：

```text
data/input/job_bigcompany_final.csv
```

用途：

- 提供每个标准岗位可使用的技能池；
- 每个岗位生成 JD 时，只能从该岗位在技能表中已有的技能中抽取技能；
- 不允许凭空生成该岗位从未出现过的技能。

岗位技能池以 `data/input/job_bigcompany_final.csv` 为准，主要根据其中的 `standard_job` 与 `skills` 字段建立岗位到技能的映射；如果文件中保留了传统技能、新兴技能相关字段，则仅用于生成阶段区分技能类型，不进入最终事件流。

技能分为两类：

1. 传统技能；
2. 新兴技能。

这两类技能只用于生成过程中的趋势控制，不直接出现在最终事件流字段中。

### 5.3 原始/归一化 JD 数据

系统采用半合成方式生成数据。

JD 文本、岗位名称可以来自现有真实数据，但必须满足：

- 岗位名称可以使用真实岗位名称；
- 该岗位名称必须能够映射到标准岗位；
- `job_responsibility` 和 `job_requirement` 尽量使用真实 JD 文本；
- 允许对同一条 JD 做轻微改动后复用，以增加样本数量和时间分布多样性。

## 6. 半合成生成方式

系统不采用完全虚构文本，而是采用“半合成”方式：

1. 从真实 JD 中抽取岗位名称、职责、要求文本；
2. 根据标准岗位映射关系，将 JD 归入某个 `standard_job`；
3. 根据系统分配的岗位趋势，决定该岗位在每个月生成多少条 JD；
4. 根据系统分配的技能趋势，从该岗位技能池中抽取部分技能；
5. 对 JD 文本进行必要的轻微改动，使其与抽取出的技能组合更一致；
6. 输出月度岗位招聘事件流。

注意：同一个岗位的技能池来自真实技能表，但每条 JD 只抽取其中一部分技能，不是把该岗位所有技能一次性全部放入。

## 7. 岗位需求趋势设计

每个标准岗位会由系统随机分配一种岗位需求趋势。

趋势分配需要保持合理性，不能完全随机到不符合常识的形态。例如：

- 大模型应用工程师、AI Infra 工程师等岗位更适合增长型或先增长后稳定型；
- 部分传统软件开发岗位可以是稳定型、缓慢下降型或波动型；
- 硬件、芯片、通信等岗位可以保持相对稳定或阶段性波动。

岗位不要求每个月都出现。

允许出现以下情况：

- 某岗位某些月份 JD 数为 0；
- 某岗位连续一段时间不出现；
- 某岗位沉寂一段时间后再次出现。

### 7.1 预设岗位需求趋势类型

建议至少包含以下趋势类型：

| 趋势类型 | 含义 |
|---|---|
| 持续上升 | 岗位 JD 数随月份整体上升 |
| 持续下降 | 岗位 JD 数随月份整体下降，后期可降为 0 |
| 先上升后稳定 | 前期增长，达到一定水平后维持稳定 |
| 先上升后下降 | 阶段性热点岗位，先增长后回落 |
| 稳定波动 | 长期保持相对稳定，但有小幅随机波动 |
| 间歇出现 | 某些月份集中出现，中间可能长期为 0 |
| 回归型 | 前期出现，中间消失，后期再次出现 |

## 8. 技能需求趋势设计

技能趋势在岗位内部生成。

对于每个标准岗位，系统需要从该岗位技能池中选择一部分技能，并为技能分配变化趋势。

技能分为：

1. 传统技能；
2. 新兴技能。

但最终生成的岗位事件流中不输出 `traditional_skills` 和 `new_skills` 两个字段。

这两个类别只作为系统内部生成逻辑使用。

### 8.1 技能出现方式

每条 JD 的 `skills` 字段是该岗位技能池的一个子集。

要求：

- 技能必须来自该岗位在 `data/input/job_bigcompany_final.csv` 中已有的技能；
- 不同 JD 的技能组合可以不同；
- 不同月份同一岗位的技能组合应体现趋势变化；
- 不能把该岗位所有技能无差别地同时塞进每条 JD。

### 8.2 预设技能趋势类型

建议至少包含以下趋势类型：

| 趋势类型 | 含义 |
|---|---|
| 稳定型 | 技能频率长期保持稳定 |
| 持续上升 | 技能在该岗位中的出现频率逐渐上升 |
| 持续下降 | 技能在该岗位中的出现频率逐渐下降 |
| 先上升后稳定 | 技能逐渐成为岗位常规要求 |
| 先上升后下降 | 阶段性热点技能，后期回落 |
| 后期突增 | 前期几乎不出现，后期快速增加 |
| 间歇型 | 只在部分月份出现，频率不连续 |

### 8.3 新旧技能趋势约束

传统技能和新兴技能的趋势分配应体现基本合理性：

- 传统技能更适合稳定型、缓慢下降型或轻微波动型；
- 新兴技能更适合持续上升、后期突增、先上升后稳定等趋势；
- 少量新兴技能可以设计为阶段性热点，即先上升后下降；
- 同一岗位下可以同时存在传统技能稳定、新兴技能上升的组合。

## 9. 输出文件设计

系统每次执行时，应输出至少三类文件。

### 9.1 岗位招聘事件流

建议文件名：

```text
job_update_event_stream_generated.csv
```

用途：

作为业务系统输入。

字段：

```text
job_id
month
standard_job
job_responsibility
job_requirement
skills
```

注意：

- 最终事件流中不包含 `traditional_skills`；
- 最终事件流中不包含 `new_skills`；
- 传统/新兴技能分类只参与生成逻辑，不直接体现在事件流中。

### 9.2 技能频率答案表

建议文件名：

```text
job_skill_monthly_frequency_answer.csv
```

用途：

作为业务系统输出结果的比对标准。

字段建议：

```text
month
standard_job
skill
monthly_jd_count
monthly_skill_count
monthly_skill_frequency
cumulative_jd_count
cumulative_skill_count
cumulative_skill_frequency
skill_trend_type
skill_stage
```

其中：

- `skill_trend_type` 表示该技能在生成时使用的趋势；
- `skill_stage` 表示该技能属于传统技能或新兴技能；
- 这两个字段用于解释和验证生成逻辑。

### 9.3 岗位趋势设计表

建议文件名：

```text
job_demand_trend_design.csv
```

用途：

记录每个标准岗位被系统分配的岗位需求趋势。

字段建议：

```text
standard_job
standard_category
job_trend_type
start_month
end_month
peak_month
start_jd_count
peak_jd_count
end_jd_count
is_intermittent
random_seed
```

### 9.4 技能趋势设计表

建议文件名：

```text
skill_trend_design.csv
```

用途：

记录每个岗位下每个技能的预设变化趋势。

字段建议：

```text
standard_job
skill
skill_stage
skill_trend_type
start_frequency
peak_frequency
end_frequency
first_active_month
last_active_month
random_seed
```

## 10. 答案表精度要求

技能频率答案表需要精确到“生成该岗位时使用的趋势”。

也就是说，答案表不仅要记录实际频率，还要记录该技能的预设趋势类型。

这样后续比对时可以同时验证两件事：

1. 系统计算出的技能频率是否正确；
2. 频率变化方向是否符合生成时设定的趋势。

## 11. 随机种子与可复现性

系统必须支持设置随机种子 `seed`。

要求：

- 同一个 seed 和同一批输入文件，生成结果必须一致；
- 不同 seed 可以生成不同但结构合理的数据流；
- seed 应记录在趋势设计表中，便于复现实验。

## 12. 系统代码与文件位置

系统代码和生成结果应放在新建文件夹中：

```text

```

建议项目目录为：

```text

```

## 13. 系统模块建议

### 13.1 输入加载模块

负责读取：

- 标准岗位词表；
- 岗位技能表；
- 可复用真实 JD 数据。

### 13.2 岗位趋势生成模块

负责为 71 个标准岗位随机分配岗位需求趋势，并生成每个岗位每个月的 JD 数。

### 13.3 技能趋势生成模块

负责为岗位下的技能分配趋势，并生成每个月技能出现概率。

### 13.4 JD 采样与改写模块

负责从真实 JD 中抽样，生成事件流中的职责、要求、岗位名称等文本。

允许对同一条 JD 轻微改写后复用。

### 13.5 技能组合采样模块

负责根据岗位、月份和技能趋势，从岗位技能池中抽取部分技能，形成该条 JD 的 `skills` 字段。

### 13.6 答案表生成模块

负责根据最终事件流计算：

- 月度 JD 数；
- 月度技能出现次数；
- 月度技能频率；
- 累计 JD 数；
- 累计技能出现次数；
- 累计技能频率。

同时保留对应的技能趋势类型。

## 14. 关键约束总结

1. 使用全部 71 个标准岗位。
2. 数据规模控制在 2000 至 3000 条。
3. 时间范围为 2024-12 至 2026-07。
4. 每月总 JD 数由趋势生成，不固定。
5. 岗位允许某些月份不出现，也允许降为 0。
6. 岗位允许一段时间不出现后再次出现。
7. JD 采用半合成方式，优先使用真实 JD。
8. 岗位名称可以使用真实名称，但必须能映射到标准岗位。
9. 技能必须来自 `data/input/job_bigcompany_final.csv` 中该岗位已有技能。
10. 每条 JD 只包含技能池中的部分技能，不是全部技能。
11. 技能只分传统技能和新兴技能两类。
12. `traditional_skills` 和 `new_skills` 只用于生成逻辑，不进入最终事件流。
13. 技能频率答案表需要记录生成时使用的技能趋势。
14. 系统必须支持 seed，保证可复现。
15. 趋势由系统随机分配，但要保持合理性。

## 15. 后续待实现内容

后续实现系统时，需要进一步确定：

1. 每种岗位趋势的数学函数形式；
2. 每种技能趋势的频率曲线形式；
3. 每个岗位每月 JD 数的上下限；
4. 每条 JD 抽取技能数量的范围；
5. 传统技能和新兴技能在不同岗位中的比例；
6. JD 文本轻微改写的具体规则；
7. 输出文件的命名规范；
8. 系统运行参数配置方式。
