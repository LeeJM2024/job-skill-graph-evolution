# 岗位数据流生成系统完整使用说明

本文档面向后续接手本项目的 AI 或协作者，说明如何运行系统、每一步会生成什么文件、各文件之间的依赖关系，以及如何判断结果是否可用。

## 1. 项目目标

本系统用于根据真实招聘数据，半合成生成一份按月更新的岗位招聘事件流，并同步生成标准答案表。

生成结果主要用于两个目的：

1. `job_update_event_stream_generated.csv`：作为输入，提供给外部岗位分析系统。
2. `job_demand_monthly_answer.csv` 和 `job_skill_monthly_frequency_answer.csv`：作为标准答案，用来和外部系统输出结果进行比对。

本系统不是爬虫，也不是岗位清洗工具。它使用已经整理好的招聘数据作为输入，生成可复现的模拟更新流。

## 2. 项目位置

项目根目录是下载或克隆后的 `岗位数据流生成系统` 文件夹，例如：

```text
岗位数据流生成系统
```

运行命令时，必须先进入这个目录：

```powershell
cd "岗位数据流生成系统"
```

除非明确需要修改输入路径，否则所有脚本都应在项目根目录下运行。

## 3. Python 运行方式

本项目使用 Python 标准库即可运行，目前不依赖 pandas、numpy 或其他第三方库。

推荐使用：

```powershell
python src\profile_inputs.py
python src\generate_job_demand_plan.py
python src\generate_skill_trend_plan.py
python src\generate_event_stream.py
python src\build_answer_tables.py
```

如果需要一次性完整重跑，可以使用：

```powershell
python src\profile_inputs.py
python src\generate_job_demand_plan.py
python src\generate_skill_trend_plan.py
python src\generate_event_stream.py
python src\build_answer_tables.py
```

注意：这五条命令必须按顺序运行，因为后一步依赖前一步的输出。

第 1 步会在 `outputs/runs/` 下创建一个新的本次运行文件夹，例如：

```text
outputs/runs/run_20260717_101530_seed_20260716/
```

同时会写入：

```text
outputs/current_run_id.txt
```

第 2-5 步会自动读取 `outputs/current_run_id.txt`，并把同一次执行的所有文件写入同一个 run 文件夹。

## 4. 目录结构

```text
岗位数据流生成系统/
  config/
    generation_config.json
  data/
    input/
      job_bigcompany_final.csv
      standard_job_title_dictionary.csv
      new_skills_current_dictionary.csv
    intermediate/
  docs/
    岗位数据流生成系统设计.md
    完整使用说明.md
  outputs/
    current_run_id.txt
    runs/
      <run_id>/
  src/
    profile_inputs.py
    generate_job_demand_plan.py
    generate_skill_trend_plan.py
    generate_event_stream.py
    build_answer_tables.py
  README.md
```

各目录含义：

- `config/`：生成参数配置。
- `data/input/`：输入数据，通常不应在运行过程中修改。
- `outputs/`：运行结果根目录。
- `outputs/current_run_id.txt`：记录最近一次运行的 run id，第 2-5 步会自动读取它。
- `outputs/runs/<run_id>/`：每次执行生成的独立输出文件夹，所有中间结果、最终事件流、答案表、质量报告都会放在这里。
- `src/`：系统代码。
- `docs/`：设计文档和使用说明。

## 5. 输入文件

### 5.1 标准岗位词表

路径：

```text
data/input/standard_job_title_dictionary.csv
```

用途：

- 提供标准岗位集合。
- 当前共有 71 个标准岗位。
- 系统会保留全部 71 个标准岗位。

关键字段：

```text
standard_job_title
standard_category
match_keywords
```

其中 `standard_job_title` 是标准岗位名称，后续生成和答案表均以此为标准岗位口径。

### 5.2 真实岗位数据

路径：

```text
data/input/job_bigcompany_final.csv
```

用途：

- 提供真实 JD 样本。
- 提供岗位名称、岗位职责、职位要求。
- 提供岗位-技能对应关系。
- 提供传统技能和新兴技能的辅助分类字段。

关键字段：

```text
job_id
job_title
standard_job
publish_time
job_responsibility
job_requirement
skills
traditional_skills
new_skills
```

注意：

- 生成事件流时，岗位技能以此文件为准。
- 最终事件流不会输出 `traditional_skills` 和 `new_skills`。
- 这两个字段只用于生成阶段的技能分类和趋势分配。

### 5.3 新兴技能词表

路径：

```text
data/input/new_skills_current_dictionary.csv
```

用途：

- 辅助识别新兴技能。
- 当前主要用于输入画像阶段和技能分类辅助。

## 6. 配置文件

路径：

```text
config/generation_config.json
```

当前核心配置：

```json
{
  "seed": 20260716,
  "month_start": "2024-12",
  "month_end": "2026-07",
  "target_total_jd_min": 2000,
  "target_total_jd_max": 3000
}
```

重要说明：

- `seed` 控制随机过程，固定 seed 时结果可复现。
- 当前生成时间范围为 2024-12 到 2026-07，共 20 个月。
- 总 JD 数量控制在 2000 到 3000 条之间。
- 如果修改 seed，需要从第 1 步到第 5 步重新运行。
- 如果修改时间范围，也需要完整重跑。

最终事件流字段由配置中的 `event_stream_fields` 控制：

```json
[
  "job_id",
  "month",
  "standard_job",
  "job_title",
  "job_responsibility",
  "job_requirement",
  "skills"
]
```

禁止出现在最终事件流中的字段：

```json
[
  "traditional_skills",
  "new_skills"
]
```

## 7. 完整运行流程

### 第 1 步：输入解析与数据画像

命令：

```powershell
python src\profile_inputs.py
```

作用：

- 读取 71 个标准岗位。
- 读取真实岗位数据。
- 建立每个标准岗位的真实 JD 样本集合。
- 建立每个岗位的技能池。
- 区分传统技能和新兴技能。
- 检查哪些岗位没有样本或技能。

生成文件：

```text
outputs/runs/<run_id>/input_profile.csv
outputs/runs/<run_id>/skill_pool_by_job.csv
outputs/runs/<run_id>/input_quality_report.json
```

输出说明：

- `input_profile.csv`：每个标准岗位一行，记录 JD 数、技能数、样例岗位名称、样例技能、质量备注。
- `skill_pool_by_job.csv`：岗位-技能池明细表，后续技能趋势生成会用到。
- `input_quality_report.json`：输入质量摘要。

当前已知结果：

```text
标准岗位数：71
有真实 JD 和技能池的岗位数：69
无真实 JD 和技能池的岗位数：2
```

无样本岗位：

```text
大数据开发工程师
FPGA工程师
```

处理策略：

- 这两个岗位仍保留在标准岗位集合中。
- 后续允许它们不出现在最终事件流中。
- 不强行伪造 JD 和技能。

### 第 2 步：岗位需求趋势生成

命令：

```powershell
python src\generate_job_demand_plan.py
```

作用：

- 生成 2024-12 到 2026-07 的月份序列。
- 给每个标准岗位分配岗位需求趋势。
- 生成每个岗位每个月的计划 JD 数。
- 控制总 JD 数在 2000 到 3000 条之间。
- 对无样本岗位生成全 0 计划。

生成文件：

```text
outputs/runs/<run_id>/job_demand_monthly_plan.csv
outputs/runs/<run_id>/job_demand_trend_design.csv
outputs/runs/<run_id>/job_demand_quality_report.json
```

输出说明：

- `job_demand_monthly_plan.csv`：岗位-月份-JD 数量计划，后续事件流生成必须严格按照它生成。
- `job_demand_trend_design.csv`：岗位需求趋势答案表，每个岗位一行。
- `job_demand_quality_report.json`：岗位需求计划质量报告。

岗位趋势类型包括：

```text
持续上升
持续下降
先上升后稳定
先上升后下降
稳定波动
间歇出现
消失后再出现
无样本不生成
```

注意：

- 大样本岗位不会被分配到强断续趋势，例如“间歇出现”或“消失后再出现”。
- 小样本岗位允许有较多 0 值月份。

### 第 3 步：技能趋势与技能概率计划生成

命令：

```powershell
python src\generate_skill_trend_plan.py
```

作用：

- 根据岗位技能池，为每个可生成岗位选择一组候选技能。
- 给每个岗位-技能组合分配技能趋势。
- 生成每个岗位、技能、月份的出现概率。
- 如果某岗位某月 JD 数为 0，则对应技能概率实际生效为 0。

生成文件：

```text
outputs/runs/<run_id>/skill_trend_design.csv
outputs/runs/<run_id>/skill_monthly_probability_plan.csv
outputs/runs/<run_id>/skill_trend_quality_report.json
```

输出说明：

- `skill_trend_design.csv`：每个岗位-技能组合的趋势设计。
- `skill_monthly_probability_plan.csv`：每个岗位、技能、月份的出现概率。
- `skill_trend_quality_report.json`：技能趋势计划质量报告。

技能趋势类型包括：

```text
稳定型
持续上升
持续下降
先上升后稳定
先上升后下降
后期突增
间歇出现
```

技能阶段包括：

```text
traditional
new
```

注意：

- `traditional` 和 `new` 是答案表和生成逻辑中的分类，不会进入最终事件流。
- 第 3 步只生成概率计划，不生成具体 JD。

### 第 4 步：JD 事件流生成

命令：

```powershell
python src\generate_event_stream.py
```

作用：

- 根据岗位月度计划生成具体 JD 行。
- 从真实 JD 中抽样岗位名称、岗位职责、职位要求。
- 根据技能月度概率抽取每条 JD 的技能组合。
- 每条 JD 技能数量控制在 4 到 10 个之间。
- 对部分复用 JD 做轻微半合成改动。

生成文件：

```text
outputs/runs/<run_id>/job_update_event_stream_generated.csv
outputs/runs/<run_id>/event_stream_quality_report.json
```

最终事件流字段：

```text
job_id
month
standard_job
job_title
job_responsibility
job_requirement
skills
```

禁止字段：

```text
traditional_skills
new_skills
```

注意：

- `job_update_event_stream_generated.csv` 是外部系统的主要输入文件。
- 每条 JD 的技能只来自该岗位在技能计划中的技能集合。
- 无样本岗位不会出现在事件流中。

### 第 5 步：答案表生成与最终校验

命令：

```powershell
python src\build_answer_tables.py
```

作用：

- 从最终事件流重新计算岗位需求答案表。
- 从最终事件流重新计算技能频率答案表。
- 检查事件流字段。
- 检查被禁止字段是否出现。
- 检查岗位需求计划和事件流是否一致。
- 检查技能是否越界。

生成文件：

```text
outputs/runs/<run_id>/job_demand_monthly_answer.csv
outputs/runs/<run_id>/job_skill_monthly_frequency_answer.csv
outputs/runs/<run_id>/final_quality_report.json
outputs/runs/<run_id>/run_summary.txt
```

输出说明：

- `job_demand_monthly_answer.csv`：岗位需求月度答案表。
- `job_skill_monthly_frequency_answer.csv`：技能频率月度答案表。
- `final_quality_report.json`：最终质量报告。
- `run_summary.txt`：简要运行摘要。

## 8. 最终交付文件

一般情况下，需要交给外部系统或下游 AI 的核心文件有三个。

### 8.1 事件流输入文件

```text
outputs/runs/<run_id>/job_update_event_stream_generated.csv
```

用途：

- 输入给外部岗位分析系统。
- 模拟从 2024-12 到 2026-07 的岗位招聘更新事件流。

字段：

```text
job_id
month
standard_job
job_title
job_responsibility
job_requirement
skills
```

### 8.2 岗位需求答案表

```text
outputs/runs/<run_id>/job_demand_monthly_answer.csv
```

用途：

- 用来比对系统是否正确计算岗位需求变化。

字段：

```text
standard_job
standard_category
month
month_index
monthly_jd_count
cumulative_jd_count
demand_trend_type
is_active_month
```

### 8.3 技能频率答案表

```text
outputs/runs/<run_id>/job_skill_monthly_frequency_answer.csv
```

用途：

- 用来比对系统是否正确计算岗位内技能需求变化。

字段：

```text
month
month_index
standard_job
standard_category
skill
monthly_jd_count
monthly_skill_count
monthly_skill_frequency
cumulative_jd_count
cumulative_skill_count
cumulative_skill_frequency
skill_trend_type
skill_stage
job_demand_trend_type
```

说明：

- `monthly_skill_frequency = monthly_skill_count / monthly_jd_count`
- 如果 `monthly_jd_count = 0`，则频率记为 `0.0000`
- `skill_trend_type` 是该技能生成时使用的趋势
- `skill_stage` 表示该技能属于传统技能还是新兴技能

## 11. 修改配置后的注意事项

### 11.1 修改 seed

如果修改：

```json
"seed": 20260716
```

必须重新运行五个脚本。

修改 seed 后，趋势分配、技能概率、事件流抽样都会变化。

### 11.2 修改时间范围

如果修改：

```json
"month_start": "2024-12"
"month_end": "2026-07"
```

必须完整重跑。

同时需要确认：

- 月份数量是否符合预期；
- 答案表行数是否随月份变化；
- 事件流总量是否仍在目标范围内。

### 11.3 修改目标数据规模

如果修改：

```json
"target_total_jd_min": 2000
"target_total_jd_max": 3000
```

只要范围合理，第二步会自动重新缩放岗位月度 JD 数。

修改后仍需完整重跑五步。

### 11.4 替换输入数据

如果替换：

```text
data/input/job_bigcompany_final.csv
data/input/standard_job_title_dictionary.csv
data/input/new_skills_current_dictionary.csv
```

必须从第 1 步开始完整重跑。

重点检查：

- 标准岗位数是否仍是预期数量；
- 是否出现新的无样本岗位；
- 是否存在不在标准岗位词表内的 `standard_job`；
- 技能池是否为空；
- 最终事件流是否仍满足字段要求。

## 12. 常见问题

### 12.1 为什么标准岗位有 71 个，但事件流只覆盖 69 个岗位？

因为当前输入数据中有两个标准岗位没有真实 JD 样本，也没有技能池：

```text
大数据开发工程师
FPGA工程师
```

按照当前设计，这两个岗位保留在标准岗位集合中，但不强行生成 JD。

### 12.2 最终事件流为什么没有 traditional_skills 和 new_skills？

这是设计要求。

这两个字段只用于生成过程中的技能分类和趋势控制，不应作为最终事件流字段输出。

### 12.3 技能频率答案表为什么很大？

因为它是按：

```text
岗位 × 技能 × 月份
```

展开的。

当前为：

```text
4569 个岗位-技能组合 × 20 个月 = 91380 行
```

### 12.4 skill_probability_plan 是否是最终答案？

不是。

`skill_monthly_probability_plan.csv` 是生成过程中的概率计划。

最终用于比对系统输出的是：

```text
job_skill_monthly_frequency_answer.csv
```

该表是从最终事件流重新计算得到的。

### 12.5 如果只想重新生成事件流，可以只跑第 4 步吗？

可以，但前提是第 1 到第 3 步输出没有变化。

如果修改了 seed、时间范围、输入数据、岗位需求计划或技能概率计划，必须从前面的相关步骤重新运行。

最稳妥做法是完整运行五步。

## 13. 给后续 AI 的操作建议

如果你是后续接手的 AI，请按以下顺序工作：

1. 先阅读 `config/generation_config.json`。
2. 再阅读本文件。
3. 确认 `data/input/` 下三个输入文件存在。
4. 从项目根目录按顺序运行五个脚本。
5. 查看 `outputs/current_run_id.txt` 确认本次运行目录。
6. 查看 `outputs/runs/<run_id>/run_summary.txt`。
7. 查看 `outputs/runs/<run_id>/final_quality_report.json`。
8. 确认最终交付文件是否满足用户需求。

不要直接手改 `outputs/runs/<run_id>/` 下的 CSV。

如果需要改变生成逻辑，应修改 `src/` 中对应步骤脚本，然后从相关步骤重新运行。
